## 2. 一分钟功能演示

彩排前在干净专用库启动离线模式：

```bash
python3 -m app.server --backend offline --db runtime/week9-rehearsal.sqlite3 --port 8001
```

浏览器打开 <http://127.0.0.1:8001>，滚动到“多轮澄清与分配确认”。不要在上方单消息入口先分配同一个订单。

1. 新建会话，发送 `Allocate cheapest; exclude W03.`，说明系统要求补订单号。
2. 发送 `ORD-045`，展示已有目标和排除条件被保留。
3. 发送 `改成两个工坊`，说明这是上限而不是必须拆成两个。
4. 发送 `不要 W8`，展示排除变为 W3/W8，干净库预览 GiantWeave、150 件、165 成本、约7.38天。
5. 时间允许时刷新页面，展示草稿和预览恢复；点击“确认分配”。
6. 在生产区域读取 ORD-045，展示 WORKING、订单版本1、W5/150件。会话关闭后不能重复提交。

上述数字依赖干净库。重复彩排使用不同库路径，或运行 `python3 -m demos.session_demo` 的自动临时库演示，不清空已有业务库。若页面现场失效，使用已经验证的命令行 demo 和保存的 JSON 解释流程；不要把预录证据冒充现场实时成功。

## 3. 必须如实表达的风险

- 真实 Gemini 冒烟成功，但全量 60 条有46条 HTTP 429，完整在线验收未通过；离线 demo 展示业务链路，不代表 LLM 品质通过。
- 多轮当前支持明确命令，每条一次修改；复杂表达用完整替换。模型不进行金额、队列和分配决策。
- 模拟器中速度目标的迟交和平均时间较低，成本、缺陷率或集中程度仍可能输给基线。
- 60条解析标注与120订单都是开发材料，没有独立 holdout 结果；30条行为正确不等于解释忠实性全部正确。
- 原始 Data Schema2 未提供；工坊数据还不是实时外部同步，本机服务没有账号权限。

## 5. 问答准备

**为什么不让 LLM 直接选择工坊？** 因为资格、费用、队列和数量守恒需要可复现规则；LLM负责将用户需求提取成结构化输入，错误输出被校验阻断。

**相比十行启发式增加什么？** 除策略结果外，还增加约束处理、澄清、候选理由、事务与幂等、部分完工和重派的审计。模拟器单独证明策略表现，接口测试证明工程与交互能力；不把它们混成一个准确率。

**为什么成本最低方案交期差？** 纯成本目标会集中选择便宜工坊，队列累积；当前默认没有硬交期约束。混合目标和明确准时约束展示不同取舍。

**多轮并发或刷新会不会重复分配？** 每回合 request_id 幂等、会话版本检查；确认前重查订单版本，生产与消息事务一起提交。刷新恢复同一会话；网络结果不明时原 key 重试。

**已经完成 Week 9 了吗？** 本轮技术准备和文字材料已就绪，正式 slides、成员资料、上传、彩排与课堂反馈仍需团队完成。
